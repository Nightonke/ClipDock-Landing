# ClipDock 官网新增语言指南

适用项目：`/Users/viktorhuang/Desktop/iOS/ClipDock-Landing`，以及从该仓库创建的工作树。

这份文档供“一个语言一个 Codex 对话”使用。目标是交付完整、自然、与 App 操作对应、可在浏览器中验收的语言版本。用户在当前对话中的范围和授权优先于本文的默认流程。

编写基准：2026-09-09，网站提交 `1ca4a1f`。目前发布 `en-US`、`zh-Hans`，有 41 篇教程、18 个工具、158 个教程使用的截图 ID、4 段演示视频。开始新任务时重新读取代码统计；这些数字是基准，不应变成阻止新增内容的固定断言。

## 1. 建议的语言顺序

ResourceDownloader 当前有下面这些语言的本地化文件。文件存在不等于翻译已完整、已人工审校或已随商店版本发布。

| 阶段 | 网站 locale / App `.lproj` | 语言 | 建议理由或处理重点 |
| --- | --- | --- | --- |
| 已有 | `en-US` / `en` | 英语 | 默认网址为 `/` |
| 已有 | `zh-Hans` / `zh-Hans` | 简体中文 | 已完成本轮措辞、功能边界与标题评审 |
| 先行 | `zh-Hant` / `zh-Hant` | 繁体中文 | 可借鉴刚评审的简中内容，并用这一轮完善通用语言接入；仍需按目标地区习惯重写 |
| 第一批 | `ja` / `ja` | 日语 | App 已有对应文案，可直接建立日语操作名称对照 |
| 第一批 | `ko` / `ko` | 韩语 | App 已有对应文案，需特别检查空格和标题换行 |
| 第一批 | `es` / `es` | 西班牙语 | 先提供一个跨地区、用词中性的版本，避免过早拆分多个地区 |
| 第一批 | `pt-BR` / `pt-BR` | 巴西葡萄牙语 | 使用巴西用语，单独对齐 App 的巴葡文件 |
| 第二批 | `de` / `de` | 德语 | 扩展语言覆盖，重点处理复合词与长按钮 |
| 第二批 | `fr` / `fr` | 法语 | 扩展语言覆盖，统一称呼、标点与不换行空格 |
| 第二批 | `id` / `id` | 印度尼西亚语 | App 已有文案；优先采用常用的产品表达 |
| 第二批 | `vi` / `vi` | 越南语 | 检查声调字符、字体与行高 |
| 第二批 | `th` / `th` | 泰语 | 检查无空格文本的分词、断行和字形 |
| 第三批 | `it` / `it` | 意大利语 | 在前两批交付后扩展 |

| 第三批 | `ar` / `ar` | 阿拉伯语 | 需要同时完成 RTL 布局和双向文本适配，工作量不能按普通翻译估算 |
| 第三批 | `pt-PT` / `pt-PT` | 葡萄牙葡萄牙语 | 与巴葡分别维护，不用巴葡内容直接冒充 |

这个顺序按现有 App 文案、复用成本和扩大语言覆盖来安排，不代表经过下载量或收入数据验证的市场排名。如果有 App Store Connect、Search Console 的地区和语言数据，应据此调整。俄语、印地语等可后续评估；目前未在 App 主工程找到对应 `.lproj`，需要先确定 App 内操作应以哪种语言为准。

网站暂时沿用表中的 locale，不自行混用 `ja`/`ja-JP`、`fr`/`fr-FR` 等两套路径。`es` 不自动等于西班牙地区版。巴葡和欧葡保留地区区别。繁中先采用台湾常用的说明文表达，App 按钮名称仍逐项以 `zh-Hant.lproj` 为准；用户指定香港等地区时再调整。

## 3. 文案和功能事实的依据

按以下分工对照，不能只把某一套语言整目录机械翻译后结束：

1. **字段、文章和步骤结构**：以当前 `src/content/tutorial-structure.ts`、`src/i18n/types.ts` 和各注册表为准。
2. **本轮修正过的功能说明与限制**：逐项对照当前 `src/i18n/zh-Hans/`。基准提交中的英文尚未同步全部简中修订，不能把英文旧有的绝对化承诺翻回新语言。
3. **英文说明和原图按钮**：参考 `src/i18n/en-US/` 与现有图片、视频；英文适合作为理解来源之一，不是所有事实冲突的最终依据。
4. **目标语言 App 界面名称**：读取 `/Users/viktorhuang/Desktop/iOS/ResourceDownloader/ResourceDownloader/<App语言>.lproj/Localizable.strings`；品牌可参考同目录的 `InfoPlist.strings`。
5. **真实功能和使用条件**：有冲突时只读检查 ResourceDownloader 中对应界面及逻辑。若仍无法证实，采用有依据的保守描述，并把具体疑点写入交付记录。

此次任务默认修改官网。App 仓库用于只读对照；遵守其 `AGENTS.md`，不为官网翻译自动执行 Xcode 编译。网站自己的构建和页面验证属于本地化交付流程。

### 建立目标语言术语表

在 `docs/localization-reports/<locale>.md` 记录核心术语，建议列为“概念 / App 原始 key / 目标语言实际值 / 英文截图名称 / 网站使用位置”。从 `.strings` 的同一个 key 取目标值，不能只按英文反查：英文 `Extract` 同时可能指“资源提取”页面和“提取”动作，`Done` 也可能对应“已完成”列表或“完成”按钮。

至少覆盖：

- 页面：资源提取、网页视频、资源管理、资源处理、视频、批量、字幕。
- 剪贴板三个设置：原始 key 为 `识别剪贴板链接自动填充`、`识别剪贴板链接自动下载`、`进入后台继续识别剪贴板自动下载`，显示文案以各语言的 value 为准。
- 下载流程：加载列表、加载下一页、全选已加载、更换链接、统一画质、跟随下载设置、加入下载队列、等待下载、下载中、已完成、失败。
- 保存流程：选择下载品质、下载设置、下载完成后自动保存到相册、保存到相册、分享文件、完成。
- 18 个工具：视频裁剪、视频转码、视频拼接、交叉拼接、分段宫格、尺寸/画布、视频旋转、视频镜像、视频变速、提取音频、音频处理、音视频合并、视频倒放、添加水印、视频转 GIF、视频转实况、视频截图、修改 MD5。
- 工具参数：推荐组合、截取范围、处理参数，以及所涉教程里的模式、枚举、会员限制。

App 显示值如有明显错误或同义词混用，操作指引引用实际入口名称，正文用自然语言解释；在记录中列出 App 的具体 key 和疑点。不要改 App，也不要自行把按钮换成用户在 App 里找不到的名字。

## 5. 不能在翻译中丢失的内容

| 项目 | 必须保留的含义 |
| --- | --- |
| 资源可用性 | 受来源、登录或访问条件、格式等影响，不能改成“所有网站都能下载”“播放就一定能保存” |
| 高清与水印 | 取决于来源提供的资源，不能保证所有视频高清无水印，也不能给音频套用画质承诺 |
| 后台识别 | 需要相应开关及画中画运行；通知还涉及设置与系统权限 |
| 批量下载 | 按页加载、选择实际返回的作品；当前免费版前 2 页限制不能漏掉，不能承诺全量频道归档 |
| 下载与相册 | App 内下载完成和保存到系统相册是不同状态；可手动保存或按设置自动保存 |
| 字幕 | 提取 YouTube 已有字幕，不提供无字幕视频转写或自动翻译 |
| 水印参数 | 本例滑块数值调低，水印变淡；不因目标语言的“透明度／不透明度”叫法反转效果 |
| 会员与参数 | 保留免费/VIP 边界、数值、单位、范围及星号含义，不承诺未验证的付费效果 |
| 示例证据 | 保留复用 TikTok 图片说明抖音、只展示保存入口、未核对 MD5、未完整试听等限制 |

保留每篇的 `verificationNote`、`exampleNote` 和相应语义。保留 slug、分类 ID、关联教程、步骤顺序、详情/FAQ/排错条数、截图 ID、示例链接、媒体时间轴，以及 `{count}` 等程序占位符。原始素材内的示例文字（如 `ClipDock Demo`）与文件名按原样引用。

同一 key 的网站品牌、人称、App/系统应用名称、平台名称、单位和标点保持一致。网站非中文品牌通常为 `ClipDock`；不要自行创造目标语言产品名。价格、评分、系统要求等继续取真实共享数据，不编造本地价格、地区支持或商店表现。

## 7. 标题、排版和 SEO

### 文字和标题

- 按目标语言组织句子，不沿用源语言词序；标题突出动作或功能，不机械重复年份、iPhone、iPad。
- 主标题、步骤标题、教程卡片、图注、视频字幕都要检查。优先缩短冗余或调整语义分行，然后按目标语言调字号、行高和布局。
- 不把简中的显式 `\n` 原样搬到其他语言；也不要用极小字号、隐藏溢出、截断标题或全局 `word-break: break-all` 掩盖问题。
- 拉丁文字不拆开普通单词；日文处理行首行尾禁则；韩文保留正确空格；泰文使用合适的断词；越南文检查组合附标；繁中使用自己的词语，不直接套简中词典。
- 检查重音符号、变音符号、标点、数字、单位、会员星号、括号与品牌混排。日期和数量可本地化显示，但不改动数据含义。
- 若扩展 `HeadingText`，测试文字内容、可访问名称、正常空格和标点，不能让分词标签把读屏文本变成不自然的逐字停顿。

### 阿拉伯语额外要求

首页和教程布局都需要正确的 `lang`、`dir="rtl"`。检查导航、目录、卡片、图文交错、箭头及交互顺序；优先采用 CSS 逻辑属性。链接、文件名、MD5、分辨率、时间码等 LTR 内容用适当的双向隔离。不要镜像品牌图标、App 截图或视频画面。不能只翻译字符串并设置右对齐就宣布 RTL 完成。

### 路由和搜索元数据

保留每种语言独立的 URL 和手动语言切换，不新增按浏览器语言强制跳转。完整翻译正文、导航与元数据；这是当前网站约定，也符合 [Google 的多语言站点建议](https://developers.google.com/search/docs/specialty/international/managing-multi-regional-sites)。

每页 canonical 指向自身；同一篇文章的语言切换保留 slug。HTML hreflang 使用完整 URL，覆盖已发布的对应页面及自身，并双向对应；`x-default` 保留对应英文页。检查站点地图、标题、描述、OG/Twitter 和 JSON-LD 的实际输出。格式按 [Google 的本地化版本规则](https://developers.google.com/search/docs/specialty/international/localized-versions)核对；目前不要用 `es-419` 作为 Google hreflang，通用西语采用 `es`。

App 界面本地化、App Store 元数据和官网本地化是不同范围。读取 `.lproj` 不能证明 App Store 已有对应介绍或关键词；参见 [Apple 的 App 信息本地化说明](https://developer.apple.com/help/app-store-connect/manage-app-information/localize-app-information)。本任务不自动修改商店资料或商店链接的地区。

## 8. 多个 Codex 对话的配合方式

**逐个做**：每个新对话从最新的已整合版本开始，完成一种语言的完整接入和验收。建议先用繁中完成通用接入，再启动其他语言。

**同时做**：每种语言使用独立 Git 工作树和分支，例如 `codex/localize-ja`、`codex/localize-ko`，不要多个对话在同一个检出目录里并行改公共注册文件。每个任务可以在自己的工作树完成语言注册、样式和测试。

开始并行前，把本指南和已完成的通用接入整合进统一基准。新工作树通常从提交创建，不会自动带上原目录里未提交的文档或代码。

- 目标语言目录和 `docs/localization-reports/<locale>.md` 由对应任务负责；其他语言译文不顺手改写。
- 公共注册表、模板、样式和检查脚本最容易冲突。整合时保留所有已完成语言，按最终代码合并逻辑，不用“全部保留本地／远端”处理这些文件。
- 通用基础修正先整合，其他分支同步后再验证。每合入一种语言，在整合后的版本重新检查全部已发布语言。
- 多个预览服务使用不同端口，并记录服务对应的工作树，避免看着别的语言任务的旧构建验收。
- 测试中途共享文件短暂不完整不能成为最终交付状态；报告未执行、失败或确实受阻的检查。
- 提交、push、发布依照用户在该对话中的要求执行；不重复询问已有授权。仅把语言加入构建列表不代表已经上线。

## 9. 验收流程

在网站工作树根目录逐项执行并检查退出状态。依赖未安装时先按锁文件安装。

```sh
npm run check:i18n
npx tsc --noEmit
npm run build
python3 scripts/verify-site.py
python3 scripts/verify-locales.py
node --test tests/videoRecovery.test.mjs
git diff --check
```

新增语言使旧检查不适用时，要改进检查对象，不要删除校验来让任务通过。例如把固定英/简中的配对检查扩展成“全部已发布语言和默认语言逐篇对应”，并让测试能捕捉缺失文章、步骤、截图、字幕或错误的语言元数据。不要固定断言永远只有 41 篇或两种语言。

注册后导出实际生效的文案通读。下面以日语为例，换语言时同时更换两个 `ja`：

```sh
node scripts/export-copy-review.cjs ja > /tmp/clipdock-ja-review.json
```

检查残留的整句源语言、空值、未替换占位符、错译的按钮、孤立尾字和重复内容。品牌、示例文件名和第一次按钮英文对照可保留；日语有汉字，不能把“发现汉字”当成“残留中文”的充分证据。

使用可用的浏览器工具打开**当前工作树构建**，按需遵循浏览器技能。推荐在 `375、390、768、1024、1440` 像素宽度检查：

1. 首页全部功能区、18 个工具、FAQ、下载区域、平台展开列表和页脚。
2. 教程列表全部卡片；逐篇检查所有教程的主标题、步骤标题和相关卡片，窄屏至少全面扫描一次。
3. 重点查看带长平台名、长按钮、会员参数和复杂图注的教程；检查对齐、断词、溢出及阅读顺序。
4. 桌面和移动语言菜单；从文章切换到其他已发布语言后仍是同一篇，再切回来。
5. 四段视频的实际字幕、轮播标签、暂停/播放入口、错误与重试文字。复用原始英文素材时确认文字指引能对应。
6. canonical、hreflang、`html lang`、`dir`、OG locale、JSON-LD 和 sitemap；确认新语言没有套用中文元数据。
7. 旧语言首页、文章与导航的回归检查。修改公共排版或 RTL 时增加相应覆盖。

保存并实际查看有代表性的桌面、手机和长标题截图。自动检查只能发现部分遗漏和溢出，不能证明翻译自然，也不能称作母语者审校。无法进行某项视觉或语义检查时，在报告中明确缺口。

## 10. 完成交付记录

每个语言创建或更新 `docs/localization-reports/<locale>.md`，避免多个对话争改同一个进度表。至少包括：

- locale、地区/文风约定、网站与 App 源版本、术语表。
- 实际完成的首页、教程、工具、图注和视频字幕范围，以及共享 404、外部法律页等例外。
- 公共注册和排版改动，以及与 App 文案有疑点的具体 key；没有疑点就写无。
- 每条检查命令的结果、浏览器/宽度/页面覆盖、截图文件位置。
- 是否已在构建中启用、是否提交、是否推送、是否部署；分别按实际状态填写。
- 尚需处理的问题；确实未解决的问题不能写成已完成。

同时更新 [现有维护说明](localization.md) 中的已发布语言现状。最终回复简要说明“新增了什么、术语如何对齐、调整了哪些排版、验证结果和未覆盖项”。
